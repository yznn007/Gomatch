# Gomatch 测试用例表

对应学校模板 `docs/school_materials/测试用例表.pdf`。四类必测：冒烟（主流程走通）/ 边界（异常输入）/ 越权（角色隔离）/ 并发（多客户端同时操作）。

## 二、边界测试（异常输入）

| 编号 | 场景 | 输入 | 预期 |
|------|------|------|------|
| B01 | 重复用户名注册 | 注册已存在的用户名 | 返回"用户名已存在" |
| B02 | 密码错误登录 | 输入错误密码 | 返回"用户名或密码错误" |
| B03 | 加入满房间 | 加入已满 2 人的房间 | 返回"房间已满" |
| B04 | 密码房间错误 | 输入错误房间密码 | 返回"房间密码错误" |
| B05 | 非己方回合落子 | 对方回合时点击棋盘 | 服务端拒绝，不更新棋盘 |
| B06 | 重复落子 | 在已有棋子的位置落子 | 服务端拒绝，返回错误 |
| B07 | 观战者落子 | 观战模式下点击棋盘 | 客户端禁用落子，不发送请求 |
| B08 | 用户名含特殊字符 | 用户名含 `|` 或换行 | JSON 编码处理，不破协议 |
| B09 | 聊天消息含特殊字符 | 消息含 JSON 特殊字符 | 正常显示，不崩协议 |
| B10 | 空消息发送 | 发送空聊天消息 | 客户端拦截或服务端忽略 |
| B11 | 不存在的房间 | 加入已解散的房间 | 返回"房间不存在" |
| B12 | 超长消息 | 发送超长聊天内容 | 截断或返回错误 |
| B13 | 单IP连接速率超限 | 单个IP在1秒内新建连接数 > 50 | 服务端限制该IP后续的Socket连接接入并进行流控 |
| B14 | 超大报文输入保护 | 发送长度 > 10MB 的超长字节流 | `BoundedLineReader` 拦截异常流，`GuardedSocket` 自动断开防范 OOM 攻击 |
| B15 | 高频消息DoS攻击 | 单个会话每秒发送 > 20 条消息 | `FixedWindowRateLimiter` 触发限流，返回错误响应并拦截非法请求 |
| B16 | 格式非法 JSON 注入 | 发送畸形不可解析 JSON 报文 | `InboundMessageParser` 捕获解析异常，防止 Socket 通信主线程崩溃 |
| B17 | Redis 快照持久化失败 | 关闭 Redis 磁盘写入权限后发起写操作 | 触发写命令时，由于设置了 `stop-writes-on-bgsave-error no`，写操作仍能正常成功并响应，不阻断正常业务 |

## 三、越权与安全测试（越权与安全隔离）

| 编号 | 场景 | 步骤 | 预期 |
|------|------|------|------|
| P01 | 观战者发落子命令 | 构造报文发送 MOVE | 服务端拒绝，返回"观战者不能落子" |
| P02 | 普通玩家发管理命令 | 构造报文发送封禁/踢人 | 服务端按 role 校验拒绝 |
| P03 | 客户端藏入口不等于安全 | 绕过客户端 UI 直接发管理命令 | 服务端仍必须按 role 拦截 |
| P04 | 查看他人对战记录 | 玩家查询他人对战记录 | 只能查自己的记录 |
| P05 | 非房主开始游戏 | 非房主点击开始按钮 | 服务端校验房主身份 |
| P06 | 被封禁用户登录鉴权 | ACTIVE 账号登录后被封禁，在重连窗口尝试重连 | `SessionAuthorizationPolicy` 拦截重连，返回拒绝并彻底清理其非法会话 |
| P07 | 恶意频繁重连攻击 | 断开连接后在 1 秒内重复发起 10 次重连 | `SessionAuthorizationPolicy` 限制请求冷却，拒绝高频重复重连 |
| P08 | 凭证伪造越权登录 | 恶意修改 `credentials.json` 中的明文凭据 | 客户端采用 `CredentialStore` 对记住的密码进行高强度加密存储防盗，服务端独立校验 Token 合法性 |

## 四、并发测试

| 编号 | 场景 | 步骤 | 预期 |
|------|------|------|------|
| C01 | 同一房间两人同时落子 | 2 个客户端同时点击棋盘 | 仅当前回合方落子成功，另一方被拒 |
| C02 | 并发注册同一用户名 | 2 个客户端同时注册相同用户名 | 仅 1 人成功，另一人收到"用户名已存在" |
| C03 | 快速匹配并发 | 多人同时快速匹配 | 匹配队列 FIFO 正确配对，不重复 |
| C04 | 多客户端同时在线 | 多个客户端同时登录 | 在线数正确递增，服务端不崩溃 |
| C05 | 断线同时重连 | 多人同时断线重连 | 会话恢复正确，不串房间 |

## 五、缺陷记录

| 缺陷ID | 关联用例 | 现象 | 期望 | 责任人 | 状态 |
|------|----------|------|------|--------|------|
| D01 | S05/S14 | Redis 进行后台 `bgsave` 失败后，所有写操作报错 `MISCONF`，排行榜无法更新。 | 排行榜与写操作不受 Redis 快照保存失败影响（通过禁用 `stop-writes-on-bgsave-error`）。 | Contributor| 已修复 |
| D02 | S01 | 并发注册同名用户时，存在 `existsByUsername` 检查与 `INSERT` 之间的竞态，数据库插入重复数据报错。 | 注册时捕获 `SQLIntegrityConstraintViolationException` 并行事务冲突，防范重复注册。 | Contributor| 已修复 |
| D03 | S04 | 快速匹配时，若队列无其他对手，原逻辑会将自己插入队列后又取出配对，导致无法等待对手。 | 先尝试取出队列中其他等待的对手；若没有，再将自己加入队列进行排队。 | Contributor| 已修复 |
| D04 | S14 | 排行榜页面在暗色主题下渲染空白，或者部分列表显示字体颜色泛白/重合。 | 主题切换后自适应注入 CSS 样式并使用 `themeColor` 动态取色，排行榜列表渲染清晰。 | Contributor| 已修复 |
| D05 | S13 | 局后战绩入库时，如果 Redis 缓存因 TTL 超期失效报错，会使整条事务中断，导致本该保存成功的 MySQL 战绩也失效。 | 事务中 Redis 异常应捕获隔离，不阻断 MySQL 持久化数据保存的成功。 | Contributor| 已修复 |
| D06 | S12 | 玩家中途加入观战房间后，只收到 `JOIN_OK`，页面无法切换到棋盘页，看不到当前对局状态。 | 观战进入时发送 `GAME_START` 命令以触发客户端棋盘 UI 渲染，并回放历史落子实现同步。 | Contributor| 已修复 |

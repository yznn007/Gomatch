# Gomatch 非 TLS 安全加固设计

## 目标与范围

在不改变现有明文 TCP 协议、不迁移用户密码存储方式的前提下，修复已经确认的会话授权、资源耗尽、房间授权、JSON 序列化、客户端凭据和默认配置风险。

本轮明确不包含：

- 用户密码哈希、迁移或登录比较逻辑调整。
- TLS、证书生成、证书分发和双向认证。
- 与安全修复无关的客户端界面重构。

## 方案选择

采用兼容式加固：保留现有 `Message` JSON 协议和 Controller 路由，只在协议边界、会话边界和配置加载处增加约束。这样可继续使用现有启动脚本，并把变更限制在可独立验证的小组件中。

未选择一次性重写网络层，因为 TLS 已明确暂缓，NIO/Netty 迁移也会扩大实训项目的回归面。未选择仅在 UI 上校验，因为恶意客户端可以绕过 JavaFX 客户端直接发送协议消息。

## 组件设计

### 1. 网络边界与限流

- 服务端在读取阶段限制单条 UTF-8 消息的最大字符数，超限后返回错误并关闭连接，避免 `BufferedReader.readLine()` 无界分配。
- `ServerMain` 按远端 IP 统计活动连接，设置每 IP 上限；连接创建与清理必须成对增减。
- `ClientHandler` 对认证前命令、登录和注册分别使用固定窗口限流。超限请求返回统一错误，不泄露账号是否存在。
- 所有分页参数统一夹取到安全范围，聊天、用户名之外的自由文本、房间名、房间密码和 Base64 输入在业务处理前限制长度。

### 2. 会话与授权

- `SessionManager` 保证每个用户只有一个有效令牌；创建新会话前撤销旧会话。
- 提供撤销用户全部会话的方法，同时清理内存、Redis 和数据库会话状态。
- 重连先检查令牌是否真实过期，再更新活动时间；随后从 MySQL 重新读取用户状态和角色。
- 被封禁用户拒绝重连；角色以数据库最新值为准；同一令牌已有活动 handler 时拒绝第二个连接。
- 封禁、密码修改和角色修改后撤销目标用户的全部会话。当前执行管理操作的管理员若需要保留连接，只更新其当前会话，禁止自降级的现有约束保持不变。

### 3. 房间访问控制

- `SPECTATE` 接收可选 `password` 字段。
- 对有密码的房间，观战与加入使用同一个常量时间不作要求的字符串校验逻辑；密码错误不进入 observers，也不设置 `currentRoom`。
- 客户端点击受保护房间的观战入口时复用现有密码输入交互。

### 4. JSON 与客户端容错

- 存档列表、聊天历史和观战历史全部使用 `JSONArray`、`JSONObject` 或 `Message.builder()` 构造，禁止字符串拼接。
- 客户端接收线程分别处理 I/O 异常和单条消息解析异常。解析失败只记录并丢弃该消息，不终止接收线程。
- 错误日志不输出完整超长报文，只记录远端地址、长度和截断摘要。

### 5. 本地凭据与配置

- “记住密码”只保存用户名和勾选状态；已有 `credentials.json` 在下次读取或登录时清除 `password` 字段。
- MySQL、Redis 和 OSS 配置优先读取环境变量，资源文件中的 localhost 开发默认值暂时保留。
- 使用默认数据库密码或空 Redis 密码启动时输出安全警告，但不阻断团队本地开发。
- 文档只描述所需变量名称，不写硬编码环境变量设置命令。

## 错误处理

- 安全拒绝统一返回现有 `ERROR`、`LOGIN_FAIL`、`JOIN_FAIL` 等协议，不把异常堆栈或基础设施错误发送给客户端。
- Redis 清理失败记录服务端警告；MySQL 中的封禁状态仍作为重连最终依据。
- 限流器只保存短期计数，定期清理过期桶，避免自身形成内存泄漏。

## 测试策略

- 单元测试覆盖：消息长度读取、固定窗口限流、分页夹取和 JSON 特殊字符序列化。
- 会话测试覆盖：封禁用户旧令牌重连失败、旧令牌被新登录撤销、同令牌并发重连失败、过期令牌不会先刷新后复活。
- 房间测试覆盖：有密码房间观战必须提供正确密码，无密码房间保持原行为。
- 客户端测试覆盖：畸形 JSON 不终止后续正常消息处理；凭据文件不再包含密码。
- 完成后运行 Maven 模块测试与编译；需要外部 OSS 凭据的现有集成测试单独标注，不作为本地安全单元测试前提。

## 验收标准

- 明文密码数据库逻辑和普通 TCP 连接方式保持不变。
- 已封禁用户无法用断线前令牌恢复身份。
- 密码房间无法绕过密码观战。
- 超长报文、暴力登录和单 IP 连接占满受到明确限制。
- 特殊字符聊天和存档名称生成合法 JSON。
- 客户端遇到一条畸形消息后仍能处理下一条合法消息。
- `~/.gomatch/credentials.json` 不再写入用户密码。

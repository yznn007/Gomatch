# 多标识登录与手机号注册设计

## 目标

用户注册时必须填写国际手机号；用户可以使用用户 ID、用户名、邮箱或手机号配合密码登录。用户名、邮箱和手机号均不能重复注册。

## 范围

- 注册页面新增国际手机号输入框，并在客户端和服务端校验和规范化手机号。
- 登录页面改为单一账号标识输入框。
- `LOGIN` 协议使用 `account` 传递账号标识。
- 服务端按用户 ID、用户名、邮箱、手机号依次匹配账号标识。
- 数据库确保用户名、邮箱和手机号唯一，并提供存量数据库迁移语句。
- 认证请求防护、DAO、测试与开发日志同步更新。

## 数据与规则

手机号为必填字段。登录与注册页都提供国家或地区区号下拉框，默认“中国 +86”；用户只填写本地号码。客户端将选中的区号与本地号码组合为 E.164 值，服务端移除空格、连字符和圆括号后校验并统一保存为带 `+` 的 E.164 形式。

注册时服务端先规范化用户名、邮箱和手机号，再分别检查重复；数据库唯一约束作为并发注册下的最终保障。邮箱统一转小写，手机号保存为带 `+` 的 E.164 形式；用户名按输入值保存。用户 ID 是主键，因此天然唯一，且不属于注册输入字段。

为避免标识歧义，登录查询顺序固定为：纯数字的用户 ID、用户名、邮箱、手机号。成功后仍返回既有的 `LOGIN_OK` 用户数据，客户端其余会话流程不变。

## 协议与组件

客户端登录控制器向 `LOGIN` 发送 `account`、所选区号组合得到的 `phone` 与 `password`；注册控制器向 `REGISTER` 发送 `username`、`email`、`phone` 和 `password`。账号输入符合当前区号下的本地号码规则时按手机号匹配；否则仍可按用户 ID、用户名或邮箱登录。

服务端 `ProtocolRequestGuard` 对 `account` 执行长度限制并使用其作为登录限流键；`ClientHandler` 完成格式校验、重复字段提示和认证编排；`UserDAO` 增加统一账号查询与手机号存在性检查。

数据库初始化脚本将 `phone` 定义为非空唯一列，并附带针对已创建数据库的迁移语句。迁移在添加唯一约束前应先检查并清理空值或重复手机号，避免静默丢失数据。

## 错误处理

- 空账号或密码：提示“账号和密码不能为空”。
- 无法匹配账号或密码错误：统一提示“账号或密码错误”，避免泄露账户是否存在。
- 手机号格式不合法：提示用户选择国家或地区区号后填写有效的本地号码。
- 注册冲突：分别提示用户名、邮箱或手机号已存在。
- 数据库唯一约束冲突：映射为对应的注册冲突提示，不暴露 SQL 异常。

## 验证

测试至少覆盖手机号格式、手机号重复注册、以用户 ID/用户名/邮箱/手机号登录、错误密码，以及认证请求限流对 `account` 字段的兼容性。完成后运行相关模块测试与 Maven 构建。
